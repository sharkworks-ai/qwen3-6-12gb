Getting started and option guide

This lab creates and evaluates compressed Qwen mixture-of-experts models. It runs on a GPU host inside a container. Your browser controls the jobs; closing the browser does not stop them.

Your first run

  1. Ask the host administrator to expose a compatible NVIDIA GPU and mount a persistent data directory. Check System for visible hardware.
  2. Open New run and choose the miniature workflow test. It creates its own small synthetic model and data. No model download is needed.
  3. Choose an unused run name and one GPU. Keep the short training budgets for a first test.
  4. Review the plan, then start. Runs shows logs, execution status and reports.
  5. Check the report. Completed execution means the stages finished; it does not mean the memory or quality checks passed.

For real-model runs, prepare a local checkpoint and datasets first. The wizard does not download them. Some advanced training stages accept remote Hugging Face IDs and need network access.

Compression choices

ChoiceWhat it changesWhen to use it
Aggressive compression (B)GSQ 2-bit routed expert weights; 3/4-bit attention and shared components.First low-bit experiment. Test quality and memory before considering stronger compression.
Extreme compression (C), experimentalCAT-Q ternary routed experts, GSQ 2/3-bit sensitive weights, and mandatory quantization-aware recovery.Compare a smaller representation when aggressive compression is insufficient. It may reduce task success.

B and C are identifiers for these two presets, not steps you must perform in sequence. Both produce research artifacts. The current packed-weight runtime is a correctness and memory test implementation, not a production serving backend. It has no fused production kernels or compressed attention cache. C uses pinned BitTern/CAT-Q code; it is not a reproduction of ScaleQ.

Prepare the model and data

All wizard paths refer to files inside the container, under {{data_root}}. A host folder mounted there can have a different name. Example: a host folder mounted at {{data_root}}/datasets is entered using that container path, not a laptop path. Relative paths such as datasets/train.jsonl resolve below the data directory.

A model checkpoint directory contains config.json, tokenizer files, and *.safetensors weights, plus a shard index for sharded checkpoints. An adapter directory or a single GGUF file is not a full source checkpoint. Real wizard sources must support 262,144 native context tokens.

JSONL means one JSON object per line. Use different files and different examples for training/calibration and held-out evaluation. Exact-file duplication is checked; this is not a complete check for overlapping content.

Training and recovery

{"messages":[{"role":"user","content":"What is 2 + 2?"},{"role":"assistant","content":"4"}]}
{"text":"User: What is 3 + 3? Assistant: 6"}

Training teaches the desired behavior. Recovery retrains after compression. Both accept text or conversational messages. Tool examples may include a tools column; use a model chat template that supports that format.

Calibration and held-out evaluation

{"text":"A representative complete conversation or document."}

Calibration guides quantization toward your workload. Held-out data measures prediction error on unseen text. Wizard calibration and held-out files use text records. The separate GGUF calibration builder writes a plain-text corpus; that output cannot be passed to the B/C JSONL input.

Teacher prompts for extreme compression

{"prompt":"Explain how to detect a cycle in a linked list."}
{"messages":[{"role":"user","content":"Plan a safe refactoring of this function."}]}

Do not include assistant answers. The teacher generates completed reasoning traces automatically. An incomplete thinking section stops the trace stage; increase its output budget in the advanced teacher-trace settings before retrying.

Understand the results

Execution completed
The program finished without an execution error. Individual checks can still fail.
Held-out loss
Prediction error on unseen text. Lower is better on the same data and token length. A negative loss change is an improvement relative to the displayed baseline. It is not a coding or agent success score.
Packed-weight parity
The compact weights produce outputs close to their reference export. This checks decoding, not whether compression preserved the original model’s quality.
Long-context retrieval
The model found a secret code placed inside a long prompt. This does not prove repository reasoning or tool use over the full history.
Memory target
A comparison against measured GPU memory. It is not an allocation cap. Testing on a 32GB GPU does not qualify a release on a physical 12GB GPU.
Resident tensor size
Memory used by model parameters and buffers. It excludes temporary work, the attention cache and other GPU allocations.
OxCoder comparison
Comparison with the pinned published scores of OrionLLM/OxCoder-9B: more than its score on at least 6 of 11 rows, at least 5 of 8 coding/agent rows, and the SWE and Terminal guardrails. Ties are not wins.
No candidate recommended
Required quality or resource evidence is missing or failed. Diagnostic-only runs cannot recommend a release.

Published coding and agent suites need an operator-configured isolated benchmark service. That service runs generated code/tools outside this training container. Without it, the wizard runs built-in diagnostics only. Imported score files must match the artifact hashes, harness revisions and all eleven score rows; see the repository’s docs/WIZARD.md for the service and evidence contract. Release approval remains separate.

Terms used in this lab

Mixture of experts (MoE)
A model with many expert weight sets. A router chooses a few for each token. Shared experts are used for every token.
Token / context
A token is a piece of text. Context is the total input and generated-output budget. A 250,000-token prompt plus 8,192 output tokens fits the native 262,144 budget; it can still run out of memory.
Quantization
Store weights at lower precision to reduce size. 2-bit weights have fewer representable values than 4-bit weights. Ternary weights use three values.
Supervised fine-tuning (SFT)
Train on examples of the output you want.
LoRA / QLoRA
Train small adapter weights rather than the whole model. QLoRA loads the base at low precision to save memory. Merge combines the adapter with its matching base checkpoint.
Quantization-aware training (QAT)
Recovery training that simulates low-precision weights, followed by quantizing the recovered model again.
GSQ / GPTQ / CAT-Q
Research methods used here to initialize and fit compact weights to reference outputs. Their advanced tuning settings are explained below.
AYOT
The teacher-reasoning calibration workflow used for extreme compression. The generated traces carry source-model provenance.
Pruning
Remove some routed experts based on measured usage. It changes the model and can lose useful behavior.
BF16 / GGUF / packed artifact
BF16 is a higher-precision research checkpoint. GGUF is a llama.cpp model file. A packed artifact is this lab’s low-bit bundle. These are different formats and are not interchangeable.
KV cache
Saved attention state used during generation. Longer prompts increase cache memory. Weight quantization alone does not compress it.
GiB / MiB / VRAM
Binary memory units: 1 GiB = 1024 MiB. VRAM is GPU memory; CPU RAM is separate.
Manifest / hash / candidate
A manifest records inputs, settings and outputs. A hash detects changes to a file. A candidate is a model variant being compared.

Stop, resume and troubleshoot

Use Stop on a running job to stop its process group. Keep the output directory. For a guided run, open its review-and-resume link and retain the same name, files, settings and code version. Changing them can invalidate saved checkpoints. Use a new name for a different experiment.

“No GPUs visible” means this container cannot see an NVIDIA device. Ask the administrator to check the NVIDIA driver, Container Toolkit and GPU exposure. The lab cannot fix host GPU setup. “GPU busy” means another recorded job uses your selected device.

For a failed stage, read Error log on the run page. Missing inputs need a valid container path. Memory failures usually need a smaller token length, batch size or reconstruction window. Benchmark failures can mean the configured service is unavailable or returned evidence for a different artifact. Do not interpret an unmeasured check as a pass.
