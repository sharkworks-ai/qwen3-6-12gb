Advanced compression stages

For a first experiment, use New run. This page launches compression or teacher-trace generation individually. Compare the presets and learn the terms.

Compression reduces the precision of stored weights. Aggressive compression uses 2-bit routed experts. Extreme compression uses three-valued expert weights and requires reasoning calibration and recovery training. Both use pinned research implementations. Outputs can be tested with the packed-weight diagnostic runtime, but still need a production serving adapter. BF16 files are higher-precision research exports, not the compact deployment model.

Extreme compression uses CAT-Q from BitTern. It is not a reproduction of ScaleQ.

Configure a compression stage

Replace the example source, data and output paths below. 4-bit attention/shared weights use more memory than 3-bit and may preserve quality better. The recovery dataset is required when recovery is enabled. Extreme compression cannot disable recovery. Sensitive-weight rules use regular expressions on Hugging Face parameter names; the first matching rule wins. The defaults for C protect the first two expert layers; replace these with measured sensitivity rules.

The plan-only action reads inputs and saves precision settings; it does not establish GPU fit. Watch logs and GPU-memory measurements on the Runs page. Resume with the same paths and settings. Changed source/config/calibration is rejected.

Generate reasoning calibration for extreme compression

Teacher traces are example reasoning responses produced by the source model (the AYOT workflow). Generate them before running extreme compression from this page. The wizard handles this dependency automatically. Use coding, tool-use and reasoning prompts in JSONL. The prompt file must contain prompt or messages fields without assistant answers. Traces must complete a thinking section.

Evaluation and publishing

The output includes precision-map.json, packed shards, a reconstruction manifest and research-hf. C also produces a recovered checkpoint and requantized output. Open Reports and tests for packed generation or model diagnostics. Use Publish only after choosing a specific output folder.

Neither preset automatically passes the release gate. Test coding, executable tool loops, long context and peak VRAM separately.
