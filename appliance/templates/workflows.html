Model engineering workflows

These controls launch one stage at a time. For an automated sequence, use New run. Example paths and remote IDs are not prepared inputs. Edit them before starting. Expand each configuration field guide or open Help. Stages with dry_run support can inspect a plan; that does not test GPU fit.

Fine-tune with small adapters (SFT / QLoRA)

Teach behavior from examples while keeping most base weights fixed. Requires a base model and training dataset. Writes adapter weights; merge them with the matching base before compression.

Measure expert usage

Measure which routed experts your examples use. Requires a source model and representative data. Writes expert_profile.json for the pruning stage.

Remove selected experts

Remove the least-used experts according to a matching usage profile. Requires the original model and expert_profile.json. Writes a new checkpoint; useful behavior may be lost.

Build a GGUF calibration corpus

Convert representative conversations into plain text for llama.cpp importance-matrix calibration. Requires a model tokenizer and dataset. This output is not B/C JSONL calibration.

Combine adapter and base weights

Requires the exact base model used to train the adapter and its adapter directory. Writes a full BF16 checkpoint for evaluation or conversion.

Export a llama.cpp model (GGUF)

Convert a full checkpoint to GGUF and reduce weight precision. Requires a compatible llama.cpp backend; optionally uses the plain-text calibration corpus. This does not create the B/C packed format or test memory and quality.
